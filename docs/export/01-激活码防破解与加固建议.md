# 对话导出 01：激活码会不会被破解？如何抬高破解成本

> 来源：CAPTCHA_SYS 项目对话  
> 日期：2026-11-27  
> 用途：评估风险；指导 IT-AMS / CONTRACT-AMS 加固改造

---

## 结论

**会。** 没有客户端授权能防住专业破解。  
当前体系能拦住的是：普通盗用、换机滥用、过期继续用。  
挡不住：有意逆向、改本地程序跳过校验的人。

**核心结论：** 授权最终若落在「本机一个文件 / 一段 if」上，就能被破解。服务端只能提高成本，不能保证防破解。

---

## 现有防护力对照

| 能力 | 作用 | 局限 |
|------|------|------|
| 服务端 `activate` / `verify` | 真伪、绑定、过期以服务器为准 | 产品若不每次联网校验，过期/作废可被绕过 |
| 一码一机 | 减少一码多人用 | `machine_id` 若在客户端生成且易伪造，可被改 |
| `API_TOKEN` | 防随意刷接口 | 若写进桌面端/安装包，可被提取 |
| 本地 `license.json` | 离线也能开 | 最易被改；跳过校验即可永久用 |

---

## 典型破解路径（概念）

1. 改客户端：跳过激活页 / 把 `verify` 结果当成功  
2. 抓包改响应或本地 mock 成功 JSON  
3. 从安装包抠出 `API_TOKEN`，或固定假 `machine_id`  
4. 断网 + 只信本地标记时，改本地授权文件

---

## 务实加固建议（五条）

1. **每次启动必须联网 `verify`，失败就锁功能**  
2. **`API_TOKEN` 不要进最终用户安装包**；由自有后端中转调激活码服务  
3. **`machine_id` 尽量稳定且难随意改**（硬件信息 + 安装实例，校验一致性）  
4. **关键功能放服务端或需在线票据**，而不是「激活一次本地永久 true」  
5. **接受现实**：面向个人盗用做到「偷码不好用、过期不好用」通常就够；面向会逆向的人，只能提高麻烦程度

---

## 一句话

用在自研软件里：**防串货、防过期、防乱激活够用**；**防专业破解不够**。  
强授权重点是「强制在线校验 + Token 不出客户端」，而不是指望激活码算法本身不可破解。
