## 1. 文档说明

### 1.1 目的

明确合同管理系统的业务目标、功能范围、数据模型、交互规则与非功能要求，作为设计、开发、测试与验收的依据。

### 1.2 产品定位

面向中小企业的**商务 / 项目 / 财务协同人员**，管理合同 **起草 → 审批 → 签署 → 履约 → 收款/付款 → 归档/到期** 的全链路，而不是只做存放扫描件的「文件柜」。提供合同台账、对内对外分类、项目关联、合同文件与版本、履约与收付款跟踪、到期提醒及操作留痕能力，解决「合同散落在网盘和微信、对内对外对不上、到期与回款靠人盯」的问题。

**关键设计决策**：对内合同（采购、外包、劳动合同补充协议等）与对外合同（销售、框架协议、NDA 等）**共用同一套台账与数据模型，仅以「方向 / 类型」字段区分**，不拆成两套系统——否则项目视角的「一项目多合同」无法一眼看清。

**不做**：完整法务知识库、复杂 BPM 流程引擎、独立手机 App（MVP 以桌面 + 局域网 Web/H5 为主）。

### 1.3 术语定义

| 术语 | 定义 |
|------|------|
| 合同台账 | 系统中全部合同的主列表与筛选视图 |
| 对内合同 | 我方作为采购/委托方等与供应商、外包方、员工等签订的合同 |
| 对外合同 | 我方作为销售/服务提供方与客户签订的合同 |
| 相对方 | 合同对方主体（客户或供应商），可维护档案 |
| 项目 | 业务项目容器；一个项目可挂多份对内、对外合同 |
| 主合同 / 补充协议 | 主合同为根；补充协议、变更协议挂在主合同下 |
| 履约节点 | 合同执行过程中的里程碑（交付、验收、质保等） |
| 收付款计划 | 按合同约定拆分的应收/应付计划，与实际到账对照 |
| 生命周期日志 | 合同创建、变更、审批、文件替换、状态流转、查看与下载的全量记录，用户不可篡改 |
| 归档 | 履约完成/终止后合同进入只读态；保留文件与日志，默认不可编辑，需显式「解档」 |
| 脱敏 | 对银行账户、统一社会信用代码等敏感字段按角色部分遮蔽显示与导出 |
| 主机模式 | 本机持有 SQLite 主库，并可对外提供局域网 API/Web |
| 激活码 | 商业化授权凭证，对接 CAPTCHA_SYS |

### 1.4 典型用户故事

> 公司同时跑多个项目。每个项目既有对外销售合同，又有对内采购/外包合同，文件很多。希望在一个系统里按项目看清合同关系、金额与回款，并在到期前提醒。

## 2. 总体需求

### 2.1 业务目标

1. 统一管理对内、对外合同，支持按项目、相对方、状态检索。  
2. 建立主合同与补充协议的层级关系，文件可版本化归档。  
3. 跟踪履约节点与收付款计划，汇总已收/未收、已付/未付。  
4. 到期、超期自动提醒，降低漏续约、漏回款风险。  
5. 关键操作可追溯（含查看与下载），敏感字段可脱敏，支持 Excel 导入导出与本地数据备份。  
6. 合同完成/终止后可归档为只读态，兼顾查询需要与实际法律效力留痕。  
7. （可选）同一局域网内多角色只读/协作查看同一份数据。

### 2.2 使用角色（MVP）

| 角色 | 职责 |
|------|------|
| 管理员 | 全部权限：配置分类、备份还原、启停局域网、授权 |
| 商务/合同管理员 | 维护合同、上传文件、推进状态、登记收付款 |
| 项目经理 | 查看并维护本项目相关合同（可配置为仅本项目） |
| 财务（只读+登记） | 查看金额与计划，登记实际收付款；不可删合同 |
| 审批人 | 按授权对「审批中」合同通过/驳回（可由管理员/商务兼任） |

> MVP 可用「简单角色 + 本机口令」实现；完整账号密码体系可二期扩展。详细权限矩阵、数据范围与脱敏规则见 **4.15**。

### 2.3 系统形态

- **桌面端（主机）**：Electron 窗口；上工具栏 + 中摘要看板 + 下合同台账。  
- **局域网 Web**：同网段浏览器访问（能力对齐或子集）。  
- **视觉**：深色专业台账风（可复用 IT-AMS 设计语言，避免默认 AI 紫白风）。  
- **数据**：本地 SQLite + 文件目录；不强制上云。

### 2.4 技术栈（与 IT-AMS 一致，已验证）

本产品与 `IT-AMS` 仓库采用**完全相同的技术栈与工程骨架**，可直接复用其已跑通的桌面主机模式，避免重复踩坑。

| 层级 | 选型 | 与 IT-AMS 的关系 |
|------|------|------|
| 桌面壳 | Electron ^33.4.9 | 同版本；主进程持有唯一主库 + IPC |
| 前端 | Vue ^3.5.13 + Vite ^6.0.5 | 同版本；Composition API |
| 数据 | **sql.js ^1.13.0**（SQLite WASM 版） | 同方案：纯 WASM、无原生编译依赖，Electron / Node 通用；单文件 `contractams.sqlite` |
| Excel | xlsx ^0.18.5 | 同库，导入导出 |
| 图表 | ECharts ^5.6.0 | 同库，金额 / 到期 / 回款率 |
| 二维码/条码 | qrcode ^1.5.4、jsqr ^1.4.0 | 同依赖（合同扫码定位 / 二期盘点式核查可复用） |
| 打包 | npm scripts + `scripts/lib/*` | 复用 `package-desktop.js` / `package-mac.js` / `make-ico.js` / `mac-bundle.js` / `zip.js` |
| 授权 | CAPTCHA_SYS | 同一激活码服务、同一 Token 体系，机器码 + `license.json` 缓存 |

### 2.5 工程骨架复用对照

> 以下为 IT-AMS 现有工程结构（已稳定运行于 V1.3）。CONTRACT-AMS 建议**原样 copying 基础设施层，只替换业务实现层**。

| IT-AMS 现有模块 | 复用方式 | CONTRACT-AMS 对应改造 |
|------|------|------|
| `packages/api-server/db.js` | **直接复用骨架** | 换库文件名 `itams.sqlite → contractams.sqlite`；`createTables()` 换成第 5 章合同域表 |
| `packages/api-server/core.js` | **复用 dispatch 模式** | `LABELS/FIELDS` 换成合同字段；`diffLogs` 复用为生命周期日志；业务路由换成合同/项目/相对方/收付款 |
| `packages/api-server/http.js`（LanServer） | **原样复用** | 局域网 HTTP 服务与 H5 访问；只读白名单改为财务/项目角色视图 |
| `packages/api-server/license.js` | **原样复用** | 机器码、激活、verify、弱网放行，仅需改产品名与环境变量前缀 `ITAMS_* → CONTRACTAMS_*` |
| `apps/desktop/main.js` + `preload.js` | **复用骨架** | IPC 通道（`api:invoke` / `service:*` / `license:*` / `app:*`）原样保留 |
| `server/index.js` + `seed.json` | 复用独立主机启动 | 种子数据换成演示项目 / 相对方 / 合同 |
| `src/components/ServicePanel.vue` | 原样复用 | 局域网服务设置面板 |
| `src/components/SettingsDialog.vue` | 复用框架 | 设置 Tab 换成合同类型、编号规则、审批阈值、脱敏规则等（见 4.13） |
| `src/components/LifecycleDialog.vue` | **改造复用** | 资产日志 → 合同生命周期日志（含查看/下载事件） |
| `src/components/ImportDialog.vue` | 改造复用 | 资产导入 → 合同台账导入校验 |
| `src/components/ChartsPanel.vue` | 改造复用 | 资产三图 → 在签金额 / 到期 / 回款率 |
| `src/components/ConfirmDialog.vue` / `ToastStack.vue` | 原样复用 | 二次确认、消息提示 |
| `src/components/ActivationDialog.vue` | 原样复用 | 激活页（客服二维码同源） |
| `src/App.vue` / `api.js` / `utils.js` | 复用外壳 | 顶部栏 + 摘要区 + 主视图 Tab；API 封装、工具函数 |
| `src/styles.css` / `components.css` / `widgets.css` | **原样复用** | 深色工业/台账视觉，保持产品家族一致性 |
| `h5/H5App.vue` + `h5.css` | 框架复用 | H5 从「盘点」改为「合同查阅 + 收付款登记（按角色）」 |
| `scripts/*` + `scripts/lib/*` | **原样复用** | 开发 / 打包 / 安装全流程 |
| `docs/激活码接入说明.md` | 参照改写 | 换成合同系统的环境变量与本地文件路径 |

**关键架构约定（必须继承）**：桌面渲染进程与局域网 HTTP/H5 **共用同一份 `core.dispatch` 实现与同一份 SQLite**，保证「同一份数据、三种入口」，不要为 H5 单独写一套业务逻辑。

**命名与路径约定**：环境变量前缀 `ITAMS_ → CONTRACTAMS_`（如 `CONTRACTAMS_DATA_DIR`、`CONTRACTAMS_LICENSE_API_BASE`）；数据目录 `data/contractams.sqlite`、`data/media/<合同编号>/`、`data/config.json`、`data/license.json`、`data/machine_id`；默认局域网端口需与 IT-AMS 错开（如 8788），避免同机双系统并存冲突。

## 4. 功能需求

### 4.1 合同台账

#### 4.1.1 列表字段（默认）

| 列名 | 字段 | 说明 |
|------|------|------|
| 合同编号 | contract_no | 唯一；可按规则自动生成 |
| 合同名称 | title | 必填 |
| 方向 | direction | 对内 / 对外 |
| 类型 | type | 如销售、采购、框架、保密、劳动合同补充等（可配置） |
| 状态 | status | 见 4.1.2 |
| 项目 | project_name | 可空 |
| 相对方 | party_name | 必填 |
| 金额 | amount | 含税或未税需在设置中约定默认口径，界面标注 |
| 签订日 | sign_date | |
| 起止日 | start_date / end_date | |
| 负责人 | owner | 商务或项目经理 |

#### 4.1.2 状态机（MVP）

```
草稿 → 审批中 → 已签署 → 履约中 → 已完成 → 已归档
                ↘ 已驳回 → 草稿
履约中 / 已签署 → 已终止（需填写原因）→ 已归档
```

规则：

1. 状态变更必须可写日志。  
2. 「已签署」建议校验：至少 1 份正文文件。  
3. 「已完成」建议校验：无未完成的必选履约节点（可配置是否强制）。  
4. 「已归档」为只读态：完成/终止后可手动或按设置自动归档；归档后不可编辑、不可替换文件，仅管理员可「解档」并写日志。  
5. 已终止合同默认保留在台账中（带终止标记），不物理删除。

#### 4.1.3 检索与筛选

- 关键字：编号、名称、相对方、项目、备注。  
- 筛选：方向、类型、状态、项目、相对方、签订年份、到期区间、是否归档。  
- 多关键字：空格/逗号分隔，OR 匹配。

#### 4.1.4 主从关系

- 创建时可选择「关联主合同」。  
- 列表可用缩进或「补充协议」标签展示。  
- 删除主合同时：若存在补充协议，禁止删除或级联询问（默认禁止，需先处理子合同）。

### 4.5 合同文件与版本

| 能力 | 规则 |
|------|------|
| 上传 | 支持 PDF / Word / 图片等；单文件建议 ≤ 50MB；单合同附件数可上限 20 |
| 正文标记 | 可指定一份为「正文」 |
| 版本 | 替换正文时自动升版本（v1、v2…），保留历史文件，填写变更说明（谁、何时、换了哪一版） |
| 下载 / 预览 | 桌面端本地打开或内嵌预览 PDF；下载/预览行为记入日志 |
| 删除 | 需确认；写日志 |
| 归档后 | 文件只读，不可替换/删除，除非管理员解档 |

存储路径示例：`data/media/{contract_no}/v{n}_{filename}`。

### 4.6 轻量审批（MVP）

不做复杂流程引擎，采用：

1. 状态进入「审批中」时，记录提交人、提交时间、备注。  
2. 管理员/指定审批人可「通过」或「驳回」。  
3. 审批意见必填（驳回时强制，通过时建议）。  
4. 设置中可配置分级金额阈值：低于阈值可直接「已签署」；超过阈值（如 ≥ 10 万）必须走一级审批；超过更高阈值（如 ≥ 50 万）需二级审批（管理员/负责人复核）。阈值与层级均可配置。  

二期再考虑多级会签、会签人并行、按合同类型走不同审批链。

### 4.12 生命周期日志

每条日志字段：时间、操作人、动作、对象（合同/文件/字段）、变更前后值、来源（桌面 / 局域网 IP）。

#### 4.15.2 数据范围

- 项目经理：通过 `contract.project_id` 限定，仅可见/维护本人负责项目的合同；无项目归属的合同对项目经理不可见。  
- 财务：可见全部合同的金额与收付款，但不可编辑合同主体信息、不可删除。  
- 局域网访问沿用同一角色体系；端口与口令由管理员控制。

#### 4.15.3 敏感字段脱敏

- 敏感字段：相对方银行账户、账号、统一社会信用代码、联系人电话。  
- 默认按角色脱敏显示（如账号 `**** **** 1234`），导出时同样脱敏。  
- 「查看明文」为独立权限，每次查看写入日志；脱敏开关与保留位数在设置中配置。  

### 4.16 账号登录与人员管理

**门禁顺序**：启动校验激活码（未激活 → 激活页）→ 账号登录（未登录 → 登录页）→ 业务界面。权限**由登录账号决定**，不提供自由切换的「视角下拉」。

#### 4.16.1 角色与默认账号

角色固定四种：`admin`（管理员）、`biz`（商务）、`pm`（项目经理）、`finance`（财务）。内置四个默认账号，初始密码统一 `123456`（可在编辑时修改）：

| 账号 | 姓名 | 角色 | 权限 / 数据范围 |
|------|------|------|----------------|
| admin | 超级管理员 | 管理员 | 全部权限；**内置，不可删除/降级/停用** |
| biz | 商务专员 | 商务 | 维护合同、文件版本、履约、收付款、提交审批 |
| pm | 项目经理 | 项目经理 | 仅可见「负责项目人 = 账号 owner_name」的项目合同；不可登记收付款、不可看人员 |
| finance | 财务专员 | 财务 | 只读 + 登记收付款；不可删改合同 |

#### 4.16.2 人员管理（仅管理员）

- 「人员」视图：列表展示账号、姓名、角色、负责项目人、状态、超级管理员标记。
- 新增/编辑/删除账号；角色固定四选一；可改密码、负责项目人、状态（启用/停用）。
- **超级管理员不可删除**，也不允许降级或停用。
- 停用账号无法登录；删除账号立即失效其全部会话。
- 密码以带盐散列存储，接口不返回密码散列。

#### 4.16.3 会话与鉴权

- 登录成功签发会话 token（持久化到 `user_session`），桌面 IPC 与局域网 HTTP/H5 均携带该 token。
- 未登录访问业务接口返回 401「请先登录」；权限不足返回 403。
- H5 端为两步：局域网访问口令 → 账号登录。

| payment_record | id, contract_id, plan_id, amount, pay_date, method, voucher_path, remark |
| approval_log | id, contract_id, level, action, operator, comment, created_at |
| lifecycle_log | id, contract_id, contract_no, event_type, target, before_value, after_value, operator, source, created_at |
| app_user | id, username, name, password_hash, role, is_super, owner_name, status, remark, created_at, updated_at |

## 6. 界面与交互原则

1. 第一屏：品牌 + 关键 KPI + 台账，避免堆砌无关营销模块。  
2. 合同详情用右侧抽屉或大弹窗，Tab 切换文件/履约/收付款/日志。  
3. 危险操作（删除、清空、还原、解档）二次确认 + 口令。  
4. 空态给出「下载导入模板」「新建第一份合同」引导。  
5. 视觉延续 IT-AMS 深色工业/台账风格，保持专业可信。  
6. 无权限的菜单/按钮直接隐藏或禁用并提示原因；敏感字段默认遮罩。
