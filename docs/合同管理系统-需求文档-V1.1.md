## 2. 版本目标

### 2.1 一句话目标

让试用用户反馈的「**看不清、建不快、文件打不开、钱对不上、票对不上**」在 V1.1 内得到可验收的改善，同时兑现「发票登记」这一对外承诺的核心能力。

### 2.2 成功标准（业务）

1. 一项目几十份合同时，可在台账/看板按项目下钻，收入与支出金额分开汇总。  
2. 从主合同一键建补充协议，编号与字段可继承，减少重复录入。  
3. 合同附件可稳定预览/下载；常见大体积 PDF 可上传并预览（见限额约定）。  
4. 开票/收票可登记并与合同、收付款关联，形成「合同 → 票 → 款」最小闭环。  
5. 收付款支持税金口径、费用分类、期次模板；违约金等可登记为计划外或专项类型。  
6. V1.0 承诺但用户踩坑的能力（导入、备份）有更清晰的入口与可靠性提升。

### 2.3 明确不做（V1.1）

| 不做 | 原因 |
|------|------|
| 企查查 / 天眼查等第三方数据对接 | 合规与成本；相对方评级继续用手工录入 |
| 真多写并发数据库改造（替换 sql.js 为服务端 DB） | 工作量大，需单独架构专项；本版仅评估方案 |
| 完整 BPM / 复杂会签引擎 | 仍以分级审批增强为主，完整会签放 P2 |
| 电子签平台对接 | 三期能力 |
| 开源完整源码 | 商业化产品策略，不在需求范围 |
| 独立移动 App | 继续桌面 + 局域网 Web |

## 4. 功能需求（增量）

### 4.1 P0 · 附件预览 / 下载修复

**问题**：用户反馈「文件与版本」下上传后，预览与下载无反应（#41、#68）。

#### 4.1.1 要求

1. 桌面端：预览 PDF 使用内嵌或系统默认打开，**必须有明确成功/失败反馈**（Toast + 错误原因）。  
2. 下载：将文件复制到用户选择目录或打开所在文件夹；失败时提示路径权限/文件缺失。  
3. 局域网 Web：预览走浏览器可打开类型；下载走标准附件响应；越权按角色拒绝并记日志。  
4. 回归范围：PDF / 常见图片 / Word（Word 至少支持下载；预览可用「用系统应用打开」降级）。  
5. 写生命周期日志：`preview` / `download` 事件在成功时必记；失败记可选 `preview_fail`。

#### 4.1.2 验收

- [ ] 新上传 PDF 可预览、可下载  
- [ ] 历史已上传文件同样可用（兼容旧路径）  
- [ ] 文件被手动删除后，界面提示「文件不存在」，不静默无响应  
- [ ] 无下载权限角色看不到下载按钮或点击后 403 提示

### 4.2 P0 · 看板 / 台账按项目下钻

**来源**：#57「一个项目中有几十份合同，看板中能不能选择分项目显示；台账能不能按项目做二级台账」。

#### 4.2.1 看板

1. 摘要 KPI 与图表支持「全部项目 / 指定项目」筛选器（与台账筛选联动）。  
2. 选择某项目后：KPI、环图、柱状、到期 Top 列表均只统计该项目下合同。  
3. 项目卡片（项目视图）增加快捷入口：「在台账中查看」「在看板中查看」。

#### 4.2.2 台账二级视图

1. 台账支持「按项目分组」展示模式：  
   - 一级行：项目名、合同份数、对外金额合计、对内金额合计、应收未收、应付未付  
   - 二级行：该项目下合同列表（字段同现有台账）  
2. 无项目合同归入「未归属项目」分组。  
3. 分组可展开/折叠；记住用户上次展开偏好（本机）。  
4. 筛选条件与分组兼容（先筛后组）。

#### 4.2.3 验收

- [ ] 选中项目后看板数字与台账列表一致  
- [ ] 分组模式下 50+ 合同的项目可流畅展开  
- [ ] 导出 Excel 时可选「当前筛选」或「按项目分组导出（含分组汇总行）」

### 4.3 P0 · 在签金额区分收入 / 支出

**来源**：#62「在签合同中能不能分类支出合同和收入合同，不然看起来总金额不对」。

#### 4.3.1 规则

1. 顶部 KPI「在签金额」拆为（或并列）：  
   - **在签收入**（默认：方向=对外，且状态 ∈ 已签署/履约中）  
   - **在签支出**（默认：方向=对内，同上）  
2. 保留「在签净额」可选指标：`收入合计 − 支出合计`（设置中可开关）。  
3. 看板环图默认按「收入/支出金额」展示，避免把对内对外金额简单相加造成误解。  
4. 口径说明文案固定展示在 KPI 旁（含税/未税沿用设置）。

#### 4.3.2 验收

- [ ] 同项目一笔对外 100 万、一笔对内 40 万时，收入显示 100 万、支出显示 40 万，不出现「在签 140 万」误导（除非用户显式看合计且有标注）  
- [ ] 筛选项目后收入/支出同步变化

### 4.4 P0 · 补充协议一键创建

**来源**：#57「签署补充协议时，能不能直接在原合同上建立，默认编号为原编号-1，引用原合同信息」。

#### 4.4.1 交互

1. 合同详情 / 台账行操作增加「创建补充协议」。  
2. 打开新建表单时自动带入：  
   - `parent_id` = 主合同  
   - 方向、类型（可改）、项目、相对方、我方主体、币种、负责人  
   - 名称默认：`{主合同名称}-补充协议`  
   - 金额默认空或 0（需用户填写变更金额）  
3. 编号规则：  
   - 默认 `{主合同编号}-1`、`-2`…（同主合同下递增）  
   - 若与全局唯一性冲突，自动跳号并提示  
4. 列表/详情展示「主合同 → 补充协议」层级；主合同详情显示子协议列表。

#### 4.4.2 验收

- [ ] 从主合同创建补充协议无需重复选相对方/项目  
- [ ] 编号按 `-n` 递增且全局唯一  
- [ ] 删除主合同仍遵循 V1.0：存在子协议时默认禁止删除

### 4.5 P1 · 发票登记

**来源**：#12「期待 V1.1 发票管理」；发布帖 V1.1 规划「发票登记」。

#### 4.5.1 目标

形成最小闭环：**合同 ↔ 发票 ↔ 收付款**，不做全量进销项税务系统。

#### 4.5.2 信息架构

```
合同详情 Tab 新增「发票」
全局主视图可增加「发票」列表（可选，P1 建议有）
```

#### 4.5.3 发票字段

| 字段 | 必填 | 说明 |
|------|------|------|
| 关联合同 | 是 | contract_id |
| 票种方向 | 是 | 开票（销项）/ 收票（进项） |
| 发票类型 | 是 | 专票 / 普票 / 电子票 / 其他（字典可配） |
| 发票号码 | 是 | 同号重复强提醒（可配置是否禁止） |
| 发票代码 | 否 | |
| 开票日期 | 是 | |
| 价税合计 | 是 | |
| 金额（不含税） | 否 | |
| 税额 | 否 | 若填价税与金额，可自动算税额 |
| 税率 | 否 | |
| 销方/购方名称 | 否 | 默认可带出相对方 / 我方主体 |
| 关联收付款流水 | 否 | 可多选或后续关联 |
| 附件 | 否 | 发票影像 PDF/图片 |
| 状态 | 是 | 草稿 / 已开具 / 已认证 / 作废 |
| 备注 | 否 | |

#### 4.5.4 业务规则

1. 合同维度汇总：`已开票合计` / `已收票合计` / `合同金额 − 已开票`（差额提示）。  
2. 对外合同默认引导「开票」；对内合同默认引导「收票」（可改）。  
3. 发票作废需写原因并记日志；作废后不计入汇总。  
4. 权限：商务/管理员可维护；财务可维护并登记；项目经理仅本项目只读（可配置允许上传影像）。

#### 4.5.5 数据模型（新增）

```
invoice (
  id, contract_id, direction, invoice_type, invoice_no, invoice_code,
  invoice_date, amount_ex_tax, tax_amount, amount_incl_tax, tax_rate,
  seller_name, buyer_name, status, remark, created_by, created_at, updated_at
)
invoice_file (id, invoice_id, file_path, file_name, created_at)
invoice_payment_link (invoice_id, payment_record_id)  -- 可选
```

#### 4.5.6 验收

- [ ] 可在合同下新增开票/收票并上传影像  
- [ ] 合同详情可见已开/已收合计与差额  
- [ ] 全局发票列表可按合同、日期、状态筛选并导出  
- [ ] 作废发票不参与合计且留日志

### 4.6 P1 · 税金、费用分类与字段可配置

**来源**：#102「缺少税金、缺少分类（材料/工资等）；合同编号/合同名称等字样希望能改」。

#### 4.6.1 税金口径

1. 合同表单增加：  
   - `amount_ex_tax`（不含税金额）  
   - `tax_amount`（税额）  
   - `amount` / `amount_incl_tax`（价税合计，与现有金额字段对齐策略见下）  
2. 设置中明确默认录入口径：**价税合计** 或 **不含税**；另一项可自动反算（税率可合同级覆盖）。  
3. KPI / 导出列可配置使用「含税」或「不含税」。

#### 4.6.2 费用 / 业务分类

1. 新增字典 `dict_category`（如：材料、设备、工资/劳务、服务、其他），合同可选 `category_id`。  
2. 台账筛选、看板分组支持按分类统计金额。  
3. 与「合同类型」并存：类型偏法务属性，分类偏费用/业务属性。

#### 4.6.3 字段显示名可配置（轻量）

1. 设置 → 显示文案：允许修改常见标签显示名（合同编号、合同名称、相对方、项目等），**不改数据库字段名**。  
2. 仅影响界面文案与导出表头；导入模板表头与配置同步。  
3. V1.1 不做任意自定义字段引擎。

#### 4.6.4 验收

- [ ] 录入税率后含税/不含税可互算  
- [ ] 按「材料/工资」等分类筛选与汇总正确  
- [ ] 修改显示名后列表、表单、导出表头一致

### 4.7 P1 · 收付款期次模板与罚息类登记

**来源**：#95「增加付款节点，比如季度付款」；#83「资金占用利息、违约金、迟延履行罚息怎么体现」。

#### 4.7.1 期次模板

1. 设置中预置模板：  
   - 一次性  
   - 首付 + 尾款（比例可配，默认 30/70）  
   - 按季度（根据合同起止日自动拆 4 期或 N 期）  
   - 自定义比例多期  
2. 「生成计划」：选择模板后批量写入 `payment_plan`，可再手工改。  
3. 已有计划时生成需二次确认（覆盖 / 追加）。

#### 4.7.2 罚息 / 违约金 / 利息

1. 收付款计划或流水增加 `nature`（性质）：  
   - 合同款（默认）  
   - 违约金  
   - 迟延履行利息/罚息  
   - 资金占用利息  
   - 其他  
2. 合同金额汇总默认**只含合同款**；罚息类在「其他收支」分区展示，避免污染回款率。  
3. 看板增加可开关指标：「违约金/罚息合计」。

#### 4.7.3 验收

- [ ] 选「按季度」能按起止日生成多期计划  
- [ ] 登记一笔违约金不改变「合同款回款率」分子分母的默认口径  
- [ ] 性质字段可筛选、可导出

### 4.8 P1 · 大附件与 PDF 预览增强

**来源**：#57「附件不能上传大于 50M；很多合同 100–200M；上传后要能预览」。

#### 4.8.1 限额与策略

| 项 | V1.0 | V1.1 |
|----|------|------|
| 单文件上限 | 50MB | 默认 **200MB**（设置可调，上限建议 300MB） |
| 预览 | 基础 | PDF 内嵌预览优先；超大文件可「仅下载/系统打开」 |
| 存储 | 本地目录 | 不变；备份时大文件耗时需进度条 |

#### 4.8.2 要求

1. 上传进度条；失败可重试。  
2. PDF 预览：优先渲染首页/可翻页；内存不足时降级为系统打开。  
3. 超过上限时明确提示当前限制值与修改入口。

#### 4.8.3 验收

- [ ] 100MB 级 PDF 可上传成功  
- [ ] 上传过程有进度；完成后可预览或系统打开  
- [ ] 备份/还原对大附件有进度与失败可恢复提示

### 4.9 P1 · 备份增强与导入体验

**来源**：#69「可以定期备份吗？异地备份」；#66「支持 Excel 导入吗」。

#### 4.9.1 备份

1. **手动备份**保持 V1.0；增加「备份到指定目录」。  
2. **定时备份（本机）**：设置每日/每周时刻，自动 zip 到指定目录；保留最近 N 份。  
3. **异地**：V1.1 不内置网盘 SDK；提供「备份完成后打开目录 / 复制路径」，由用户自行同步到网盘。文档中说明推荐做法。  
4. 备份任务失败写日志并 Toast。

#### 4.9.2 导入体验

1. 工具栏「导入」旁增加「下载模板」常驻入口。  
2. 空态引导文案明确「支持从 Excel 批量导入合同」。  
3. 导入结果报告：成功 N / 失败 M，失败行号+原因可复制。

#### 4.9.3 验收

- [ ] 可配置每日自动备份并滚动保留  
- [ ] 新用户 3 步内能完成：下载模板 → 填写 → 导入

### 4.10 P2 · 用印申请（可延期至 1.1.x / V1.2）

### 4.13 P2 · 局域网多用户并发评估

## 7. 数据迁移

1. 版本号写入 `settings`：`app_version = 1.1.x`。  
2. 迁移脚本幂等：  
   - `contract` 增加 `amount_ex_tax`、`tax_amount`、`tax_rate`、`category_id`（可空）  
   - 新建 `dict_category`、`invoice*` 表  
   - `payment_plan` / `payment_record` 增加 `nature`，默认 `contract`  
3. 旧数据：`amount` 视为价税合计；不含税/税额留空，由用户后续补录。  
4. 升级失败可回滚至升级前自动快照。
