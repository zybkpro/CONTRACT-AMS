## 1. 文档说明

### 1.1 目的

V1.1 解决了"看不清、建不快、文件打不开、钱对不上、票对不上"。V1.2 聚焦用户在实际使用中暴露出的**三大顾虑**：

1. **数据敢不敢删、备份能不能恢复** —— 用户"一直没敢用删除功能，怕把合同扫描件删了"；
2. **辛苦录入的数据会不会误点就没了** —— 用户反馈点弹窗旁边就把界面关了、输入半天的东西全没了；
3. **软件在老系统能不能装、装上能不能打开** —— Win7 报"不是有效 win32 程序"、Win10 64 位"进程在但没窗口"。

同时补齐多币种、合同类型、收付款体验等实用向诉求。

### 1.2 与 V1.1 的关系

- V1.1 基线能力（发票、项目下钻、收支分列、补充协议、税金分类、期次模板、备份 zip、7 天试用与 CAPTCHA_SYS 授权）**全部保留**。
- 本文只写 **V1.2 增量**：新增功能、体验改造、缺陷修复。
- V1.1 延期的 P2（用印、OCR、多级会签、局域网真并发）继续不在 V1.2 范围，见 §2.4。
- 未在本文重述的规则，默认沿用 V1.1 PRD。

## 2. 版本目标

### 2.1 一句话目标

让用户可以**放心地删、完整地恢复、误点了不丢数据、老电脑也能打开**，并把多币种与收付款打磨到"跨国合同也能对账"。

### 2.2 成功标准（业务）

1. 用户可从任一备份 zip 一键恢复合同、附件、设置，恢复后可正常打开附件与看板。
2. 删除合同默认进入回收站，附件不立即物理删除；30 天内可原样恢复（含附件、流水、日志），清空回收站才真正删除。
3. 录入/编辑表单时点击遮罩不再直接丢弃数据：要么不关闭，要么关闭后草稿仍在、下次打开自动回填。
4. Win7 64 位用户有明确可执行的安装包或替代方案；Win10 64 位"有进程无窗口"有自检与一键兼容模式。
5. 可自定义币种（USD/EUR/CHF 等）与汇率，合同可按原币记录、按本币汇总，看板 KPI 口径明确。
6. 新增"项目收款合同 / 项目支付合同"类型，按项目归集应收应付更直观。

### 2.3 本期产品状态（V1.2 前置）

- 当前产品版本 V1.2.0，分支 `v1.2`，本轮已交付：7 天试用 + CAPTCHA_SYS 授权、首次登录强制改密、设置弹窗固定高度与局域网服务回归、H5 免账号密码（只输口令）、强制改密后会话失效的修复。
- 备份导出、附件上传（含图片）、币种字段（默认 CNY）在 V1.0/V1.1 已存在，本期是**增强**而非从零建设。

### 2.4 明确不做（V1.2）

| 不做 | 原因 |
|------|------|
| 用印申请、全文检索/OCR、多级会签 | V1.1 已列 P2，继续顺延，优先级低于数据安全 |
| 局域网真多写并发（替换 sql.js） | 架构专项，单独评估 |
| 云同步 / 多租户 SaaS | 定位仍是本地 + 局域网轻量台账 |
| 在线实时汇率自动抓取 | 合规与稳定性考虑，V1.2 只做手工汇率录入 |
| 合同全文在线编辑（富文本） | 附件已可上传文本/图片，在线编辑属三期 |

## 4. 功能需求（增量）

### 4.1 P0 · 备份一键恢复

**用户原话**："备份完数据，怎么恢复数据呢？恢复数据功能可以做一下么。"

**现状**：V1.1 有"备份导出 zip"（含数据库 + 配置 + 附件）和"Excel 导入自恢复"（清空后重导 Excel 自动建档案），但**没有从备份 zip 恢复到本机的入口**。用户导出后不知道怎么还原。

**目标**：设置 → 数据管理 → 新增「**从备份恢复**」按钮。

| 项 | 需求 |
|----|------|
| 入口 | 设置 → 数据管理区，"备份"按钮旁增加"从备份恢复"，明确提示"恢复将覆盖当前全部业务数据" |
| 文件格式 | 识别 V1.1/V1.2 备份 zip（内含 `contractams.sqlite`、`config.json`、`media/`、可选 `settings.json`） |
| 恢复流程 | 选择 zip → 校验完整性（zip 可解压、含数据库、版本兼容）→ 二次确认（输入"恢复"）→ 覆盖写入 → 重启应用加载 |
| 保护 | 恢复前自动把当前数据再备份一份（防止误恢复）；恢复失败回滚，不留下半套数据 |
| 范围 | 恢复合同/项目/相对方/发票/收付款/日志/附件文件；账号与系统设置是否覆盖给选项（默认不覆盖账号，仅覆盖业务数据与配置） |
| 反馈 | 恢复成功显示"恢复完成：N 份合同、M 个附件"；失败给出具体原因（文件损坏 / 版本不符 / 磁盘空间不足） |
| 日志 | 恢复操作写入生命周期日志（操作人、来源文件、时间、结果） |

**验收**：导出备份 → 清空数据 → 从备份恢复 → 合同数/附件/发票/流水与备份时一致，附件可正常预览下载，看板统计正确。

### 4.2 P0 · 合同软删除与回收站

**用户原话**："如果要删除一个合同信息，他会提示关联的图片与附件文件将一并从主机数据目录清除，操作会保留在日志中供导出追溯。一直没敢用这个功能，别真的把合同扫描件删除了那就惨了。"

**现状**：`DELETE /api/contracts/:id` 直接调用 `db.removeMediaFile()` **永久删除物理附件文件**，并删除合同及所有关联表记录。用户的担心完全属实——误删无法挽回。

**目标**：把"永久删除"改为"**软删除 + 回收站**"，物理文件不再立即删除。

| 项 | 需求 |
|----|------|
| 默认行为 | 删除合同 → 移入回收站，合同标记 `deleted_at`，附件**原地保留不删除**，界面从台账隐藏 |
| 回收站入口 | 台账工具栏或设置中增加「回收站」，列出已删除合同（编号、名称、删除时间、操作人、附件数） |
| 恢复 | 单份/批量恢复，恢复后合同与附件、流水、日志原样回到台账；补充协议层级关系保留 |
| 永久删除 | 回收站内"彻底删除"才真正删除物理附件与记录，需二次确认（勾选 + 输入"彻底删除"），并提示不可恢复 |
| 保留期 | 默认 30 天；到期自动清理（可在设置配置天数，0 = 不自动清理） |
| 文案修正 | 原删除确认文案"关联文件将一并从主机数据目录清除"改为"删除后将移入回收站，30 天内可恢复；彻底删除才会移除附件文件" |
| 备份联动 | 备份应包含回收站数据，恢复后回收站内容一并还原 |
| 日志 | 删除、恢复、彻底删除均写生命周期日志，可导出追溯 |

**验收**：删除合同 → 附件文件仍在磁盘 → 回收站恢复 → 附件可打开、数据完整；彻底删除后文件才消失；全程日志可查。

### 4.3 P0 · 表单草稿保护（点遮罩不丢数据）

**用户原话**："录入信息的时候，或者编辑已有的信息，或者点开设置，再输入界面的旁边任意位置点击鼠标就会取消当前界面……误点了直接关闭，输入半天的数据啥也没有了。希望取消界面鼠标功能，或者改为即使取消了，数据也能保留。"

**现状**：`ContractDialog.vue`、`ContractDetail.vue`、`SettingsDialog.vue`、`ImportDialog.vue`、`InvoicePanel.vue` 等大量弹窗根节点使用 `@click.self="emit('close')"`，点击遮罩即关闭且**不保存任何输入**。

**目标**：双保险——**敏感表单禁止点遮罩关闭** + **草稿自动保存**。

| 项 | 需求 |
|----|------|
| 录入/编辑表单 | `ContractDialog`（新增/编辑合同）、`ImportDialog` 等含输入的弹窗：**移除 `@click.self` 关闭**，只能通过"保存/取消/右上角 ✕"关闭；点"取消"时若有改动需二次确认 |
| 设置弹窗 | 同上：有未保存改动时点遮罩/✕ 关闭需提示"有未保存的修改，是否放弃？" |
| 草稿自动保存 | 新增/编辑合同表单输入时，把表单内容自动存到本地草稿（localStorage，按"新建"或合同 id 区分）；意外关闭后再次打开自动回填，并提示"检测到未保存草稿，已为您恢复" |
| 草稿生命周期 | 保存成功或用户明确"放弃草稿"后清除；草稿含时间戳，超过 7 天自动失效 |
| 只读详情 | `ContractDetail` 抽屉（无输入）可保留点遮罩关闭 |
| 其它弹窗 | 确认类小弹窗（删除确认等）可保留点遮罩关闭（无数据丢失风险） |

**验收**：新建合同填一半 → 点遮罩 → 弹窗不关闭（或关闭后重开自动回填）→ 数据不丢；设置改了几项未保存点遮罩 → 提示确认；保存/放弃后草稿清除。

### 4.4 P0 · Windows 兼容性

**用户反馈**：
- "Win7 64 位提示不是有效 win32 程序"；
- "Win10 64 位打开什么也不显示，任务管理器里能看到程序在运行"。

**现状**：打包基于 Electron 33.4.9。**Electron 从 v23 起已停止支持 Windows 7/8**，Win7 上 exe 无法运行属预期；Win10"有进程无窗口"常见于无独立显卡/远程桌面/旧驱动下的 GPU 渲染失败。

**目标**：

| 项 | 需求 |
|----|------|
| Win7 方案（二选一，需决策） | ① 提供 **Win7 兼容版**：基于 Electron 22（最后支持 Win7 的分支）单独打包，功能对齐但标注"兼容版"；② 在发布帖明确"不支持 Win7，最低 Win10 64 位"，提供升级引导。**建议①**，因用户明确在 Win7 环境 |
| Win10 无窗口诊断 | 启动时写运行日志到 `data/app.log`；检测到渲染进程启动超时给出提示 |
| 兼容模式开关 | 提供一键"安全模式启动"（等效 `--disable-gpu --disable-software-rasterizer` 等兼容参数），可做成随包 `win-safe-mode.bat` 或在设置中提供重启到兼容模式 |
| 首启自检 | 首次启动检测系统版本、显卡加速可用性，给出对应引导（Win7 提示兼容版、GPU 异常提示安全模式） |
| 发布说明 | 发布帖与 README 明确支持矩阵：Win10/11 64 位（主推）、Win7 64 位（兼容版）、macOS arm64/x64 |

**验收**：Win7 64 位运行兼容版可正常启动登录；Win10 64 位无窗口环境用安全模式参数可显示界面；不支持环境给出明确提示而非静默失败。

### 4.5 P1 · 自定义币种与汇率

**用户原话**："可以在设置中把金额的单位设置为自定义么，可以增加其他币种，像我们公司合同遍布好几个国家，有用美金结算的，有用法郎结算的等等。希望能增加一个金额单位的选项，可以在金额单位后面有一个汇率输入框，可以自定义输入汇率。"

**现状**：合同有 `currency` 字段（文本，默认 CNY），但无币种字典、无汇率、无本币汇总；看板金额直接把各币种数值相加，**跨国合同统计口径不准**。

**目标**：

| 项 | 需求 |
|----|------|
| 币种字典 | 设置 → 增加"币种管理"，预置 CNY/USD/EUR/CHF/GBP/JPY 等常用币种，可自定义新增（代码、名称、符号） |
| 汇率录入 | 每个币种可录入对人民币汇率（1 外币 = N 人民币），手工维护并标注"汇率更新日期"；V1.2 不做在线抓取 |
| 合同表单 | 币种由自由输入改为下拉选择；金额按原币录入，界面同时显示"折合人民币 ¥X（按汇率 N）" |
| 本币汇总 | 看板与台账合计提供"按原币"和"折合人民币"两种口径切换；默认折合人民币，并注明汇率口径与更新日期 |
| 历史汇率 | 汇率变更不影响历史合同的折算口径——合同保存时记录当时的汇率快照；看板可按"签订时汇率"或"当前汇率"切换 |
| 导出 | 导出 Excel 增加"币种""汇率""折合人民币"列 |
| 迁移 | 老库 `currency` 为自由文本：能匹配字典的自动关联，不能匹配的保留为自定义币种并提示用户补汇率（默认 1） |

**验收**：新增 USD 合同按 7.2 汇率录入 → 看板折合人民币正确；改汇率为 7.3 后，按"签订时汇率"仍显示旧折算、按"当前汇率"显示新折算；导出列齐全。

### 4.6 P1 · 项目收款合同与支付合同

**用户原话**："建议建立项目收款合同与支付合同。"

**现状**：合同用"方向（对外/对内）+ 类型（销售/采购/外包/劳动补充/NDA…）"区分，没有专门归属到某个项目、明确"收款/支付"角色的合同类型。

**目标**：

| 项 | 需求 |
|----|------|
| 新类型 | 合同类型字典增加"项目收款合同""项目支付合同"两类（可配置、可改名） |
| 项目绑定 | 这两类合同**必须选择所属项目**，且项目视图的"应收/应付"按这两类自动归集 |
| 项目资金视图 | 项目卡片/详情增加"收款合同合计、支付合同合计、净额"，与收付款实际到账联动 |
| 与现有方向兼容 | 项目收款合同默认方向=对外，项目支付合同默认=对内，可改；不影响既有合同统计口径 |
| 筛选 | 台账可按这两种类型筛选，看板可展示"项目收付净额" |

**验收**：建两个项目收/付合同 → 项目视图显示收/付合计与净额 → 台账按类型筛选正确 → 老合同统计口径不变。

### 4.7 P1 · 附件类型增强与图片预览

**用户原话**："能上传文本和图片就好了，纸质合同很重要。"

**现状**：V1.1 已支持任意文件上传（上限 200MB，可设 300MB）、PDF 预览；图片文件可作为附件上传但**没有专门预览体验**，也没有"快速文本记录"入口。

**目标**：

| 项 | 需求 |
|----|------|
| 图片附件 | 图片（jpg/png/webp 等）上传后生成缩略图，合同详情内点击可放大预览、多图浏览；仍可下载原件 |
| 纸质合同扫描件 | 增加"扫描件"文件标记，合同详情按"正文/扫描件/补充材料"分类展示 |
| 文本速记 | 合同详情增加"文字备注/摘录"输入（纯文本），可随合同保存、导出，便于把纸质合同关键条款录进去 |
| OCR | 本期**不做** OCR 自动识别（沿用 V1.1 P2 决定），仅做图片预览与文本速记 |
| 兼容性 | 图片预览在桌面端与 H5 均可用；大图按原尺寸展示、加载有状态提示 |

**验收**：上传扫描件图片 → 详情可缩略图浏览与放大 → 文字备注可保存导出 → H5 端同样可预览。

### 4.8 P1 · 收付款体验优化

**用户原话**："基本够用了，就是收付款有点不太好用。"

**现状**：V1.1 有 plans（期次模板）、records（流水）、性质分类、罚息不计入回款率。用户反馈笼统，需细化落地。

**目标**（先做高频痛点，具体交互可在设计阶段再确认）：

| 项 | 需求 |
|----|------|
| 批量登记 | 收付款流水支持一次录入多笔（表格粘贴/逐行添加），减少逐笔点击 |
| 计划-流水对照 | 期次计划列表直接显示"已收/已付、差额、最近登记日"，点期次即可登记，不必切换到流水 Tab |
| 筛选与排序 | 流水列表按日期/金额/性质/方向筛选排序；支持按合同、按项目汇总 |
| 快速更正 | 流水登记错误可编辑/作废（留日志），不必删除重录 |
| 回款率口径 | 明确展示回款率计算方式（已收/应收，按合同或按项目），与罚息排除规则一致 |
| 引导 | 首次进入收付款 Tab 给 3 步引导（建计划→登记流水→看差额），可关闭 |

**验收**：批量登记 5 笔流水成功；期次页可见差额并快速登记；流水可筛选排序；回款率与看板一致。

## 7. 数据迁移

- 新库老库统一走 `db.js` 的幂等迁移（`PRAGMA table_info` + ALTER / CREATE TABLE IF NOT EXISTS）。
- 老库 `currency` 自由文本 → 匹配币种字典，未匹配保留并默认汇率 1。
- 老库无 `deleted_at` → 默认 NULL（未删除）。
- V1.1 备份 zip 无版本标识 → 按旧格式兼容读取，恢复后补写版本标识。
